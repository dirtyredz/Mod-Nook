# GOTCHAS — Mod Nook

Non-obvious traps. Each: the trap → why → what to do. Most are load-bearing quirks of grafting onto
the game's own live UI; the code comments are the source of truth, this is the index.

## Build & repo

- **Don't edit `Directory.Build.props` or `pack.ps1` here.** → They're workspace-synced canonicals
  generated by `../../tools/sync-mod-files.ps1`; a local edit gets overwritten. → Change them at the
  workspace source and re-sync.
- **Don't hardcode a version in `Plugin.cs`.** → It's single-sourced from `<Version>` in
  `src/ModNook.csproj` via `ModBuildInfo.Version`. → Bump the csproj only, and only when publishing.
- **`HEAD` is committed but unreleased (`3f5f65f`, WIP) on top of live 1.0.0.** → Expected; don't
  "fix" the version mismatch or rush a publish. → Publish only after in-game validation (ROADMAP P2).
- **Building needs the game's `Managed/` DLLs** at the Steam path in `Directory.Build.props`; they're
  referenced with `<Private>false</Private>` and must **never** be copied next to the plugin or
  committed. → Same for `save-backup-*/`, `dist/`, `bin/`, `obj/`, decompiled game code.

## Grafting onto the game UI

- **The overlay is parented to the canvas, not the PauseScreen.** → So hiding the pause screen doesn't
  hide it; without this it survives Esc and looks like it reopened itself. → `OnHide` closes it
  explicitly (`CloseFor`).
- **On Linux/Proton the canvas ancestor may still be inactive at `OnShow`.** → A plain
  `GetComponentInParent<Canvas>()` returns null and the overlay parents wrong. → Use
  `includeInactive: true`.
- **Don't cache game widget templates across opens.** → The PauseScreen is destroyed and rebuilt
  between sessions, so a captured template becomes a destroyed object and a dialog built from it
  renders with no buttons (a dialog you can't leave). → `ButtonTemplate` is re-resolved every `Open`.
- **Fit the pause panel at end-of-frame, not inline.** → Every mod adds its pause button from the same
  `OnShow` in load order, so measuring inline counts only buttons added before us and the panel grows
  a little each visit. → `FitWhenSettled` yields `WaitForEndOfFrame` first.
- **When cloning the settings backdrop/header, destroy the clone's `UIScreen` components first.** →
  `UIScreen` registers itself by type on Awake, so a live clone would take the real screen's place in
  the registry and the game would drive ours. → Also strip `UIScreenBackground` (its click dismisses
  the screen) and localization (`LocalizedTextField` rewrites its own text from Awake). Hold the
  cloned **GameObject**, not the component you cloned through (the sweep destroys that component).

## Dialogs & popups

- **Close open dialogs before hiding the overlay.** → Dialogs are children of the overlay; one left
  open comes back with the overlay and sits over everything. → `Close` (and `RequestBack`) call
  `ModalDialog.CloseCurrent()` — one handle tears down whatever modal is up — then `Tooltip.Hide()`.
  Since a single `ModalDialog.current` replaced the three per-type statics, there is no longer a list
  of names to keep in sync: a new dialog kind is covered the moment it subclasses `ModalDialog`.
- **The game text popup opens *behind* our overlay unless the overlay stands down.** → The overlay is
  the canvas's last sibling and blocks raycasts, so the popup is unclickable and Escape never reaches
  it. → `SuspendOverlay` drops `OverlayGroup.blocksRaycasts` (and the dialog's own blocker) and
  restores it on the popup's `OnScreenHide` (covers Escape/cancel, not just confirm).
- **Custom dialogs (key/colour/list) deliberately do *not* juggle `blocksRaycasts`.** → They're
  children of the overlay, so standing the overlay down would kill their own raycasts and clicks fall
  through to the pause menu. → Each carries its own full-screen blocker instead.
- **Register the dialog singleton *before* building its UI.** → A throw mid-build would otherwise
  leave an un-closeable half-built dialog. → `ModalDialog.Show<T>` assigns `current` before calling
  the subclass `Build()`, so the contract is enforced once in the base — subclasses can't get it wrong
  (two of the three used to, assigning it *after* `Build`).
- **The text popup's prefix label is hidden, not blanked.** → Emptying the string leaves the object in
  the layout so the "Name:" gap stays; and it's the game's own creature-naming dialog, which needs the
  label back. → Hide the object and re-show it on `OnScreenHide`.

## Widget mapping

- **`KeyCode` must be matched before the `enum` branch.** → `KeyCode` *is* an enum, so it would render
  as a cycle over every key on the keyboard (how Minimap / Save Anywhere once looked). → The key
  branch is checked first in `Rows.Build`.
- **Seed a widget's value before adding its change listener.** → Otherwise seeding the initial state
  reads as a change and rewrites the config file on every page build. → e.g. set `ToggleValue` first,
  then `AddListener`.
- **Only bounded numbers get sliders.** → Without an `AcceptableValueRange` there's no honest way to
  draw a track, so an unbounded number falls back to a text field. → Not a bug; document a range in
  the mod (or see BACKLOG for inferred ranges).
- **The prose choice-parser is intentionally conservative.** → "a comma-separated list of things" in a
  description is otherwise indistinguishable from a real enumeration. → It only fires when the
  setting's current value is one of the parsed tokens, tokens are short, unique, and 2–12 in number.
